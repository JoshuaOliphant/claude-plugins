# Notes: stale on-disk cache (L1)

The cause is in `freightdesk/pricing/dimensions.py`. `profile_parcel(carrier, l, w, h, kg)` is wrapped in `@memoize_to_disk("parcel-profile")` (from `utils/diskcache.py`), whose key is the function name plus its canonicalised arguments. Inside, the function calls `get_tariff(carrier)` and reads `dim_divisor` and `weight_step_kg` from the current rate card, so that rate-card data affects the result but never reaches the key. The shipped `tree/var/cache/parcel-profile/` holds 67 entries. Four of them (Nordline 45x35x18@2, 50x40x30@4, 30x30x30@2.2, 38x28x24@1.9) were written under Nordline's earlier divisor of 6000. `data/tariffs/nordline.json` now says 5000 (revision 2026-07). The stale entries' `created` stamps fall in April–June, while the fresh Nordline dim-dominant entries are from July onwards. For these four parcels only, the old, lower dimensional weight is served and the parcel drops a weight band. Someone reading from the symptom goes `cli.cmd_quote` → `QuoteService.quote` → `quote_shipment` → `RatingEngine.price` → `_price_parcel` → `profile_parcel`. Along that path the arithmetic is correct, and the tariff file, bands, zones and surcharges all check out against the rate card. Re-running the same box at 2.1 kg is correct because it's a cold key, so the defect only shows by observing runtime state: the returned `dim_weight_kg` (4.73 instead of 5.67) traced back to a cache hit, or the result changing under an empty `FREIGHTDESK_CACHE_DIR`. Decoys:
- the same `@memoize_to_disk` decorator on `utils/holidays.public_holidays` (pure in its arguments) and `adapters/fx_rates.reference_rate` (historical rates that never change), both with shipped cache entries that are correct;
- `functools.lru_cache` on `utils/postcodes.normalize_postcode` and `pricing/zones._lanes`;
- module-level memo globals `_LOADED` (tariffs), `_TABLE` (FX), `_settings` (config), `_caches` (diskcache) and `_RENDERERS` (render);
- a float sum in `render_csv`;
- a Saturday-delivery date adjustment in `services/transit.py`.

The reference fix passes the divisor and weight step into `profile_parcel` explicitly, so the key covers everything the result depends on. Deleting or rebuilding the stale entries also satisfies the tests, which only check user-visible output against a cold cache and the published rate card.
