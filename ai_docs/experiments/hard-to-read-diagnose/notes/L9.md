The cause is `deep_merge` in `basketry/utils/mapping.py`: it starts from `dict(base)` and only recurses into nested mappings that the override also supplies, so every nested value the request does *not* supply (here `fulfillment.inserts`, or the whole `fulfillment` dict when omitted) is the very object stored in the channel template that `OrderTemplates` parses once and keeps for the life of the shared `api` service. `OrderDecoder.decode` (adapters/codec.py) merges each request onto that template and `build_dataclass` passes the list straight into `Fulfillment`, so when `PackingPlanner.plan` appends gift-wrap/gift-card/sample inserts to its own order's `fulfillment.inserts`, it is appending to the template's list, and every later request on the same channel that omits `inserts` inherits them; requests that send their own `inserts` are unaffected, which is why only some receipts leak. The symptom path (cli `summarize` -> `OrderService.summarize` -> packing/summary/render) looks correct: the planner legitimately annotates the order it was given, the summary copies labels into a fresh list, and `deep_merge`'s docstring truthfully says neither input is modified (the bug is aliasing in the *output*), three hops from the CLI via codec -> templates/mapping. Decoys using the same idioms that are correct or irrelevant: `Catalog._parsed` is a class-level dict cache shared across instances (products are frozen); `CustomerStore` hands out the same mutable `Customer` (with a `tags` list) to every request but nothing mutates it; `PromotionEngine.DEFAULT_RULES` is a class attribute copied with `list(...)` and `last_rejections` is reset each evaluate; `SummaryBuilder.reset` and `Journal.reset` rebind instead of clear (harmless because nothing else holds the old objects, and the journal snapshots details via a JSON round-trip); `deep_merge` is also used in `config.load_settings`, whose result is frozen; `TaxCalculator.rates_for` mutates only a `dict(...)` copy; the top-level `coupons` list from the template is aliased the same way but never mutated; `Contact` is built from the shared template dict but only its dataclass attribute is reassigned; and module-level globals (`api._service`, the renderer registry) are intentionally process-wide.
