The cause is in `ledgerkit/exporters/excel_eu.py` together with the class attribute it inherits: `DelimitedExporter` (in `exporters/delimited.py`) declares `extensions = (".csv",)` as a default for its subclasses, and `ExcelEuropeExporter` never overrides it, so at import time `Exporter.__init_subclass__` registers *both* `csv` and `excel-eu` for `.csv`; `Registry.register` lets the later registration take the extension, and which module is imported later depends on the unsorted `os.scandir` walk in `utils/discovery.py` (on this machine `csv` wins, under reversed/sorted listing `excel-eu` wins). The symptom's path (`cli.cmd_export` → `export_service.export_ledger` → `resolve_exporter` → `Registry.for_extension`) is all correct code, and `excel_eu.py` itself says nothing about extensions, so a reader sees no claim on `.csv`; the conflict only shows up in runtime registry state (`ledgerkit formats` lists `.csv` under whichever exporter won, and `-vv` logs the takeover) or by forcing a different listing order. Simply sorting the scan does not fix it (`csv_export` < `excel_eu`, so excel-eu wins), nor does making the registry first-wins (in reversed order excel-eu registers first); the conflict itself must be resolved (reference fix: `extensions = ()` on the EU dialect). Decoys: the importer package uses the same unsorted discovery helper and also registers `.csv`/`.json` by extension (no overlaps); `JsonLinesExporter` and `TsvExporter` inherit from other exporters but correctly override `extensions`; `formatting/numbers.py` has its own `__init_subclass__` auto-registry with dict overwrite plus `LEDGERKIT_LOCALE`/`LANG` environment lookups that look like a plausible "CI locale differs" cause (they only affect Markdown/HTML/summary); `config.py` layers `conf.d/*.ini` where later files win and `LEDGERKIT_*` env vars override (sorted, deterministic); `formatting/templates.py` scans a directory with `os.scandir` (sorted); the CLI `COMMANDS` dict and validation `CHECKS` list are decorator registries with unique keys; and the registry's `log.debug` on extension takeover looks like the bug site but is just reporting it.
