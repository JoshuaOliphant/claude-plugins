# Resume Best Practices Reference

## Formatting & Structure

### ATS-Friendly Formatting
- Single-column layout (multi-column confuses parsers)
- Standard section headings: Summary, Experience, Skills, Education, Projects
- No tables, text boxes, headers/footers, or images
- Use standard bullet characters (-, *)
- Consistent date formatting (Month YYYY or MM/YYYY)
- Standard fonts: Arial, Calibri, Garamond, Times New Roman, Helvetica
- 10-12pt body text, 14-16pt headings
- 0.5-1 inch margins

### Length Guidelines
- Entry-level (0-5 years): 1 page, 400-500 words
- Mid-level (5-10 years): 1-2 pages, 500-700 words
- Senior/Executive (10+ years): 2 pages max, 600-800 words
- Optimal keyword density: 475-600 words per page
- Never exceed 2 pages unless academia/federal

### Section Order (Recommended)
1. Name + Contact Information (header)
2. Professional Summary (3-4 lines)
3. Technical Skills / Core Competencies
4. Professional Experience (reverse chronological)
5. Education & Certifications
6. Projects (optional, especially for career changers)
7. Publications / Awards (if relevant)

## Professional Summary

### What Works
- 3-4 lines maximum
- Lead with career level + specialization
- Include 2-3 top skills matching the job
- Mention a quantified achievement if possible
- Match the job's language (e.g., "full-stack" vs "backend")

### What to Avoid
- "I am writing to..." or first-person pronouns (debatable, but safer for ATS)
- Generic statements ("hardworking team player")
- Objectives ("Seeking a position where...") — use summary instead
- Summary statements produce **340% more callbacks** than objectives (Ladders study)

### Template
```
[Career level] [title/specialization] with [X years] of experience in [domain].
Proven track record of [quantified achievement]. Expertise in [top 3 skills matching job].
[Optional: industry-specific credential or differentiator].
```

## Experience Section

### Bullet Point Structure
- Start every bullet with a strong action verb (past tense for previous roles)
- Follow the **CAR formula**: Challenge → Action → Result
- Include metrics in **70%+ of bullets** (revenue, users, time saved, efficiency)
- 3-6 bullets per role (most recent roles get more)
- Most recent role: 4-6 bullets. Older roles: 2-4 bullets.

### Quantification Guide
- Revenue/cost: "Reduced infrastructure costs by $2.4M annually"
- Scale: "Managed platform serving 50M daily active users"
- Speed: "Cut deployment time from 4 hours to 15 minutes"
- Team: "Led cross-functional team of 12 engineers"
- Percentage: "Improved API response time by 40%"
- Volume: "Processed 2.5TB of data daily across 200+ microservices"

### What to Avoid in Experience
- Job descriptions (what the role was) vs. achievements (what you accomplished)
- Passive voice ("Was responsible for...")
- Vague claims without metrics ("Improved performance significantly")
- Listing technologies without context ("Used Python")
- Better: "Built real-time data pipeline in Python processing 10K events/second"

## Skills Section

### Organization
- Group by category: Languages, Frameworks, Cloud/Infrastructure, Databases, Tools
- List skills by proficiency (strongest first)
- Match job posting terminology exactly (e.g., if they say "Kubernetes", don't say "k8s")
- Include certification abbreviations in parentheses (AWS SAA, CKA)
- 15-25 skills total (too many dilutes signal; too few misses keywords)

### Skills Placement Strategy
- Place skills section immediately after summary for keyword-heavy roles
- ATS systems often scan top-to-bottom; earlier placement = better matching
- Mirror the job posting's exact phrasing for critical skills

## Career Gaps

### How to Address
- Brief, factual explanation (1 line)
- Highlight any upskilling during the gap
- Frame positively: "Career sabbatical for professional development"
- Don't hide gaps — ATS flags unexplained date inconsistencies
- Acceptable: "Professional Development (2023) — Completed AWS Solutions Architect certification"

## Remote Work Emphasis

### For Remote-Friendly Roles
- Mention distributed team experience
- Highlight async communication skills
- Reference tools: Slack, Notion, Linear, GitHub, Zoom
- Quantify remote collaboration: "Coordinated with 3 time zones across 5 countries"

## Common Resume Mistakes

1. **Typos and grammar errors** — Use spell check, but also human review
2. **Generic resume for every application** — Always customize per job
3. **Including references** — "References available upon request" is assumed
4. **Including photos** — Not standard in US/UK (standard in some EU countries)
5. **Using personal pronouns** — "I managed" vs "Managed" (ATS neutral, but convention favors no pronouns)
6. **Outdated skills** — Remove technologies >10 years old unless relevant
7. **Inconsistent formatting** — Same bullet style, date format, spacing throughout
